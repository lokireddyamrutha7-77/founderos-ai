# AI Advisor Failure Cases

This document records possible Gemini Advisor failures and how FounderOS handles them.

| Failure case | Detection | Current handling | Next improvement |
|---|---|---|---|
| Missing API key | `GEMINI_API_KEY` is empty | Raise `ValueError` before calling Gemini | Convert to the shared API response contract during integration |
| Invalid or revoked key | Gemini returns HTTP 401 or 403 | Convert the Gemini error into `AdvisorGenerationError` | Display a safe configuration message |
| Invalid model | Gemini returns HTTP 404 | Convert the Gemini error into `AdvisorGenerationError` | Keep the model name configurable through `.env` |
| Rate limit exceeded | Gemini returns HTTP 429 | Return a controlled Gemini API error | Add bounded retry before deployment |
| Gemini service failure | Gemini returns HTTP 500–599 | Return a controlled Gemini API error | Connect the validated fallback through the API layer |
| Slow response | Request takes too long | Response time is measured during live testing | Add a request timeout through the API layer |
| Empty response | `response.text` is empty | Raise `AdvisorGenerationError` | Allow the API or frontend to retry |
| Malformed JSON | Pydantic cannot parse the response | Reject the response | Structured output reduces this risk |
| Missing required field | Pydantic validation fails | Reject the response | Preserve the locked nine-field contract |
| Unexpected extra field | Pydantic validation fails | Reject the response | Prevent downstream contract changes |
| Incorrect field type | Pydantic validation fails | Reject the response | Log validation details during development |
| Incorrect nested-item count | Pydantic validation fails | Reject the response | Preserve competitor, SWOT, revenue, growth, and next-step counts |
| Weak startup description | Input is shorter than 10 characters | Reject before calling Gemini | Frontend should request more detail |
| Excessive startup description | Input exceeds 5,000 characters | Reject before calling Gemini | Frontend should show a character counter |
| Hallucinated market facts | Unsupported claims appear in the analysis | Prompt tells Gemini not to invent evidence | Add grounded sources in a later phase |
| Invented location details | Output contains unsupported city names, local statistics, or local laws | Prompt requires general evaluation criteria instead | Add automated location-safety evaluation later |
| Jurisdiction-specific legal advice | Output claims exact local legal requirements | Prompt restricts output to general compliance categories | Add a legal-safety evaluation before production |
| Missing professional disclaimer | Legal output does not recommend professional advice | Live test checks for consultation and professional-advice wording | Keep the disclaimer visible in the frontend |
| Fallback contract mismatch | Cached response fails Pydantic validation | Reject the fallback during tests | Validate the fallback during CI |
| Database metadata generated by Gemini | Gemini returns `id` or `created_at` | Structured schema rejects unexpected fields | Generate both values only in the backend/database |

## Locked Nine-Field Generation Contract

FounderOS uses Gemini structured output with a Pydantic JSON schema.

The Gemini-generated Advisor response contains exactly:

1. `idea_score`
2. `market_validation`
3. `competitors`
4. `swot`
5. `business_model`
6. `revenue_suggestions`
7. `growth_strategy`
8. `legal_considerations`
9. `next_steps`

The response is accepted only when:

- All nine required fields are present.
- All values have the correct type.
- `idea_score` is between 0 and 100.
- Exactly three competitors are returned.
- Every SWOT category contains exactly three entries.
- Exactly three revenue suggestions are returned.
- Exactly three growth stages are returned.
- Exactly five next steps are returned.
- Legal considerations remain general and recommend consulting a qualified professional.
- No unexpected fields are present.
- Gemini does not return database-generated `id` or `created_at`.

The persisted/read-response schema will extend the nine analysis fields with backend-generated `id` and `created_at`.

## Demo Fallback

FounderOS includes a cached demonstration response in
`backend/ai/fallback.py`.

The fallback:

- Is intended only for the known demonstration idea.
- Contains exactly the nine Advisor analysis fields.
- Is validated using the same `AdvisorReport` Pydantic schema.
- Includes safe, general legal considerations.
- Does not contain database-generated `id` or `created_at`.
- Must not be presented as a live Gemini response.

The API integration layer will decide when to return the fallback if the live Gemini request is unavailable during the demonstration.
